4.1 Merge Sort

Merge sort is a divide-and-conquer algorithm that was invented by John von Neumann in 1945. It works by recursively breaking down a problem into two or more sub-problems of the same or related type, until these become simple enough to be solved directly.

PYTHON 
def mergeSort(arr):
    if len(arr) > 1:
        mid = len(arr)//2
        L = arr[:mid]
        R = arr[mid:]

        mergeSort(L)
        mergeSort(R)

        i = j = k = 0

        while i < len(L) and j < len(R):
            if L[i] <= R[j]:
                arr[k] = L[i]
                i += 1
            else:
                arr[k] = R[j]
                j += 1
            k += 1

        while i < len(L):
            arr[k] = L[i]
            i += 1
            k += 1

        while j < len(R):
            arr[k] = R[j]
            j += 1
            k += 1

The time complexity of Merge Sort is O(n log n) in all 3 cases (worst, average and best) as merge sort always divides the array into two halves and takes linear time to merge two halves.

Certainly! Let's break down the O(n log n) complexity in brutalist terms:

  • The 'log n' Part (Dividing): Think of the tree structure. Every time you divide the array in half, you add a level to the tree. If you start with 8 items: 8 → 4 → 2 → 1. That's 3 divisions. Log base 2 of 8 is 3. So, the height of the dividing tree is exactly log n.
  • The 'n' Part (Merging): At every level of that tree, you have to merge all the sub-arrays back together. Merging two sorted arrays takes linear time proportional to their combined length. Across any single level, you are essentially looking at all n elements once to merge them.

Multiply the number of levels (log n) by the work done at each level (n), and you get the total structural cost: O(n log n).
